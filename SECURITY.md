Security Policy

Supported Versions
VaultForge is maintained on a semi‑active basis. Security updates are provided only for the latest stable version when necessary and as time permits.

Version	Supported

Latest	✅ (semi‑active)

Older	❌


Users are encouraged to always update to the newest release, as older versions may not receive security fixes.

Reporting a Vulnerability

If you discover a security vulnerability in VaultForge, please report it responsibly. Do not open a public GitHub issue. Security issues should be reported privately to avoid exposing sensitive information.

How to report

Please send an email to:
securityVaultForge@proton.me
(If no security email is available, an alternative contact method should be provided.)

Include the following information:

A clear description of the vulnerability

Steps to reproduce the issue

Potential impact

Any suggested fixes (optional)

What to expect

You will receive an acknowledgment within a reasonable timeframe.

If the vulnerability is confirmed, a fix will be developed as soon as possible, depending on availability.

You will be informed when the issue is resolved.

If the report is invalid or not considered a security issue, you will receive an explanation.

Responsible disclosure

Please do not publish the vulnerability before it is fixed, share exploit details publicly, or test attacks on systems you do not own. VaultForge appreciates responsible security research and will credit contributors if desired.

Security Scope

VaultForge is a local password manager. It does not provide cloud synchronization, remote access, or network communication. Security reports should focus on encryption implementation, key derivation, data storage, access control, auto‑lock behavior, and password handling.

Third‑Party Dependencies
VaultForge uses third‑party cryptographic libraries. Each dependency is subject to its own license and security policies.
